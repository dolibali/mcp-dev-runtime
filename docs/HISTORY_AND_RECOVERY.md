# 执行历史、日志查询与运行诊断（1.2.0 / 契约 3.1）

## 保留策略

默认 `exec.retained_session_ms=null`：不按经过时间删除已完成的内存执行记录。`0` 也是关闭时间淘汰的兼容写法；正整数仍表示从命令结束开始计算的毫秒数。读取记录不会延长一个显式配置的保留时间。

内存仍受容量限制：默认最多 8 个活动执行、512 条已结束记录、单会话 8 MiB 输出、全部会话合计 64 MiB 输出。已结束记录按完成顺序淘汰；活动任务不被历史清理终止。日志字节上限可能让活动任务的较早输出被淘汰，返回 `output_gap=true`。这些是日志预算，不是整个 Node 进程及其子进程的内存上限。

重试去重独立使用 `request_cache_ttl_ms`（默认 600000）与 `request_cache_entries`。命令仍活动时，其创建请求的去重条目被固定保护，不受完成结果的 TTL 或容量淘汰影响。进程结束后才释放保护并重新计算完成保留时间。复用同一标识但改变参数会失败；重复请求重放原始响应快照，应通过会话句柄查询当前状态。完成缓存仍有边界，不承诺跨重启或永久 exactly-once。

后台维护独立使用 `exec.maintenance_interval_ms`，不会因为禁用 TTL 形成高频循环。

## 磁盘历史与隐私

`history.enabled` 默认开启，目录默认为相对于运行时 `cwd` 的 `.mcp-dev-runtime/history`。部署时可以显式配置专用绝对目录；不要让多个活动服务共用同一个历史目录。

默认保存执行标识、实例、时间、工作目录、状态、退出码，以及调用方显式提供的 `label`。默认 **不保存命令正文，不保存原始 stdout/stderr，不保存交互 stdin**。命令字段显示 `[not recorded]`。标签和工作目录也可能包含私人信息，应按本地敏感数据管理。

需要保留构建或测试日志时，在启动任务时指定 `capture_output=true`。写入从任务开始时接收输出，不能在任务结束后再从可能已截断的内存缓存补造完整日志。配置 `history.record_output=true` 可以改为默认记录所有任务的输出，但输出可能包含密钥、终端输入回显和其他敏感内容；应慎用。`history.record_command=true` 会另外保存最多 4096 UTF-8 字节的命令预览。关闭记录设置不会自动删除过去已保存的数据。

目录权限为 0700，文件为 0600；这是本机文件权限，不是加密或针对同用户进程的沙箱。这里没有“自动识别并脱敏所有秘密”的保证。默认输出不落盘是隐私边界，不能以不可靠的通用脱敏替代它。

磁盘默认最多 4096 条记录、总计 256 MiB，单条原始日志最多 16 MiB；异步输出写入队列默认 1 MiB。达到记录数或总容量后轮转最旧的非活动记录；不为腾出空间终止活动任务。原始日志保存有界前缀，达到单日志配额后停止保存后续原始输出，而不是悄悄改写偏移。`archive_truncated`、`history_warning`、`archive_output_bytes` 明确说明不完整存档。磁盘空间或写入队列不足不会被包装成完整保存。

历史写入失败时，本地命令仍可继续执行；`history_state=degraded` 和诊断信息会提示问题。磁盘失败诊断在当前实例中保留，避免故障被后续成功调用掩盖。可以在修复原因后通过健康检查确认，并在没有活动任务时重启刷新存储状态。

历史目录使用单写入者锁，防止两个服务同时改写索引和轮转文件。无法确认的锁不会自动删除；已确认原进程退出的锁可以安全回收。损坏或异常类型的元数据不会被静默当成正常记录加载；普通命令不因此失去执行能力。

## 查询示例

启动一个有标签且保存原始输出的任务：

```json
{"cmd":"npm test","workdir":"/path/to/project","label":"project/test","capture_output":true}
```

查看当前实例的内存记录：

```json
{"scope":"current","workdir":"/path/to/project","label":"test","order":"desc"}
```

跨内存淘汰和重启查历史（调用 `list_exec_sessions`）：

```json
{"scope":"history","workdir":"/path/to/project","label":"test","outcome":"failure","limit":20}
```

`scope=current` 默认按创建顺序升序，`scope=history` 默认降序。`workdir` 为精确的路径解析后匹配，`label` 为区分大小写的子串。`outcome` 支持 `success`、`failure`、`unknown`。列表游标绑定当前实例、过滤条件和创建序列快照，不能换过滤条件后沿用，也不能跨服务重启沿用。容量淘汰仍可能让快照中的旧条目不可用。

用当前执行句柄只看最后 100 行（调用 `write_stdin`）：

```json
{"session_id":123,"tail_lines":100,"max_output_tokens":4000}
```

尾部查询保留原始换行和 UTF-8 边界，返回受字节预算限制的后缀。超过预算或扫描窗口时返回 `tail_truncated=true`；不能把它说成全部请求行都已返回。`tail_lines` 不与 `output_cursor` 或 `search` 同时使用。

按字面字符串搜索：

```json
{"session_id":123,"search":"error","max_matches":20,"max_output_tokens":2000}
```

搜索不是正则表达式。匹配结果放在 `matches`，`output` 为空；每项含实际 UTF-8 字节位置与有限长度预览。后续调用把 `search_next_cursor` 放入 `output_cursor`，直到 `search_has_more=false`。单次扫描最多 1 MiB，跨窗口匹配不会因为 UTF-8 或查询字符串边界被丢失。不得使用普通的 `next_output_cursor` 当搜索继续位置。

尾部和搜索都不推进默认增量输出游标，不接收终端输入。正常增量读取和显式重放的原有语义不变。

从历史列表取出 `session_id` 与 `archive_id` 后读取磁盘日志：

```json
{"session_id":123,"archive_id":"<从历史列表取得的完整标识>","tail_lines":100}
```

历史读取默认从偏移 0 开始，没有隐式持久游标；分页时显式传 `output_cursor`。有效档案读取偏移上限为 `archive_output_bytes`，它可能小于进程已观测的 `total_output_bytes`。`has_more=false` 只表示该可读存档没有剩余片段，不能用来否定 `archive_truncated`。

只保存了元数据的任务返回 `OUTPUT_NOT_RECORDED`；被容量轮转移除的存档返回 `HISTORY_NOT_FOUND`。不要因此重跑有副作用的命令。

## 重启与不确定结果

历史可查询不等于进程可恢复。旧实例执行句柄不能用于新实例输入或终止；历史日志读取明确是只读操作。服务关闭时仍按原逻辑终止自己创建的活动进程。

启动时读到一个旧实例未记录最终状态的任务，会以 `unknown` 返回，退出码、结束时间和信号均为 null。这不代表任务失败或仍在运行，只代表本次服务无法确认最终结果。不会根据旧 PID 恢复或终止一个可能已复用的系统进程。

完成元数据采用临时文件写入、文件同步与原子替换；日志异步串行写入，在任务结束时同步。已验证正常重启和进程 SIGKILL 后的历史恢复。这不是磁盘硬件断电、网络文件系统或所有文件系统崩溃语义的保证。

## 运行诊断与日志轮转

`npm run status` 现在除生命周期状态外，还返回近期主动探测的 `health.availability`、MCP 实例、Tunnel 就绪状态、检查时间，以及诊断日志统计。默认每 5 秒探测；状态查询会刷新明显过期的健康数据。生命周期的 `state=ready` 不再被当作永远可用的唯一证据，应同时看 `health`。

`npm run doctor -- --json` 检查实际配置、工具链、PTY、本地健康和官方 SDK 的六工具发现/Schema 一致性，不执行用户 Shell 命令。`--offline` 只检查配置和本机工具环境。可以用 `--config FILE` 指定目标；不会把其他实例的启动器状态冒充这个目标的状态。

`/healthz` 继续区分服务存活与资源状态，并提供活动/保留会话数、输出预算、受保护重试条目、磁盘历史状态、RSS 与运行时间。

MCP 与 Tunnel 诊断日志在运行期间轮转，默认每文件 10 MiB、保留 3 份（当前文件计入），以异步写入和背压限制积压。超长无换行诊断行仍被显式省略，已知传输密钥仍脱敏。低频 `launcher.log` 是后台启动/退出报告文件，保留原来的启动时轮转；它不承载运行中的命令输出流。

临时就绪检查失败只更新健康状态，不会自动重跑用户命令，也不会因一次探测失败杀掉正在运行的 MCP 任务。子进程真正退出仍保留协调关闭行为；这里没有添加自动重启/自动排队系统。真实网络重连由已固定版本的 Tunnel 自身处理，本轮不修改其源码或配置。

本地 MCP/Tunnel 就绪不等于 ChatGPT 广域网调用已验证。需要另外做当前宿主客户端实际调用验证。

## 主动清除与升级

停止目标服务、确认无其他写入者后：

```sh
node dist/launcher/cli.js history-clear --config config.json --confirm
```

没有 `--confirm` 会拒绝；有活动写入者也会拒绝，不会自动停止服务或删除不属于该存储的目录。不会删除源代码或执行命令产生的其他文件。历史元数据已损坏时需要先诊断，不会假装成功清除了全部历史。

升级后重启 MCP 以加载新代码和 Schema。六个工具名称保持不变；新增参数需要客户端刷新其缓存的工具定义。默认时间淘汰被关闭，不会迁移或重建旧版本中已经丢失的内存记录。原始输出必须在启动任务时明确开启落盘。
